# Komponentforslag: hvordan fargeverktøy og designsystemer foreslår og forhåndsviser farger på UI-komponenter

Notater per 2026-10-08. Sitater står på originalspråket. Versjoner er oppgitt der kilden sier det; mange nettsider (m3.material.io, atlassian.design, carbondesignsystem.com, developer.apple.com HIG) er JavaScript-renderte og ga tomt innhold ved henting, så flere tall er hentet fra de offisielle token-kildefilene (AndroidX Compose Material 3, Fluent UI React v9, Primer Primitives) i stedet. Det er markert i hver kilde.

## 1. Hvilke verktøy viser levende komponentforhåndsvisning fra en palett, og hva viser de?

### Takeaway
De beste verktøyene (Material Theme Builder, Realtime Colors, Happy Hues, uicolors.app, Coolors Visualizer, Huemint) viser paletten som et «miniprogram» eller en nettside, ikke som enkeltruter; de fleste bruker 4–5 roller (bakgrunn, tekst, primær, sekundær, aksent) og bare Material Theme Builder og Realtime Colors gir tydelig kontrastvurdering per element. Ingen av de undersøkte palett-verktøyene viser interaksjonstilstander (hover/trykket/fokus/deaktivert) eksplisitt – det gjør bare designsystemenes egne «playgrounds» (Radix Themes, Material Theme Builder-komponenter).

### Cited Findings
- **Realtime Colors** (Juxtopposed): fem roller – «Text», «Background», «Primary (for main CTAs and sections)», «Secondary (for less important buttons and info cards)», «Accent (for images, highlights, hyperlinks, and cards)». Paletten legges på en komplett nettsidemal; mørk/lys byttes med Alt+T; kontrast vises med tre nivåer: «x / Red: does not pass AAA or AA... - / Yellow: might pass AA but won't pass AAA... ✓ / Green: passes both AA and AAA». Eksport: CSS, Tailwind, SCSS, fargetoner («color shades»), gradienter, HEX/RGB/HSL/OKLAB/OKLCH — [Realtime Colors](https://www.realtimecolors.com/)
- Realtime Colors beskrives som verktøyet som «lets you edit and preview your color palette live across headings, buttons, cards, and layouts» — [dev.to: 4 free tools to visualize your color palette on real UI components](https://dev.to/darwinphi/4-free-tools-to-visualize-your-color-palette-on-real-ui-components-18pe)
- **Material Theme Builder** (Google, material-foundation): input er «seed»/kildefarge eller egne verdier for primary, secondary, tertiary, error og neutral, med «color match», justerbart kontrastnivå og skjemavarianter (tonal spot, vibrant, expressive). Forhåndsvisningen viser knapper, FAB, kort, navigasjonslinje, tekstfelt, chips og dialoger i sanntid, med lys/mørk-bryter. Eksport: Figma, DSP, Material Tokens JSON, Jetpack Compose, XML, CSS — [Material Theme Builder](https://material-foundation.github.io/material-theme-builder/)
- Material Theme Builder «helps you see how Material Design 3's dynamic color and new type scale will look in your app»; eksportarkivet inneholder «values» og «values-night» med egne «themes.xml» for lyst og mørkt tema — [material.io blog: Start building with Material You](https://material.io/blog/start-building-with-material-you)
- Material Theme Builder fikk støtte for Figma Variables (rapportert 2025) — [TheTechOutlook](https://www.thetechoutlook.com/new-release/software-apps/material-theme-builder-now-gets-the-support-for-figma-variables/)
- Material Design Color Tool beskrives med «Built-in contrast checking (WCAG AA/AAA)» og «auto-generated light/dark themes» — [dev.to](https://dev.to/darwinphi/4-free-tools-to-visualize-your-color-palette-on-real-ui-components-18pe)
- **Radix Colors «Custom palette»**: «Use the custom color palette tool to generate a Radix Colors scale based just on a couple reference colors.» Utdata: «Radix Colors steps 1 through 12, as well as their alpha variants and wide-gamut color definitions», pluss «Surface color, used by certain `variant="surface"` components; Indicator color, used by components like Checkbox, Radio, and Tabs; Track color, used by components like Slider and Progress Bar». Mørkt tema: «toggle the appearance to dark in the website header». Siden sier ingenting om komponentforhåndsvisning — [Radix Colors: Custom palettes](https://www.radix-ui.com/colors/docs/overview/custom-palettes)
- **Radix Themes**: «Accent color is the most dominant color in your theme. It is used for primary buttons, links and other interactive elements.» ThemePanel «allows you to preview the theme in real time», og det finnes en «component playground» — [Radix Themes: Color](https://www.radix-ui.com/themes/docs/theme/color); [Radix blog: Themes 3](https://radix-ui.com/blog/themes-3)
- **Happy Hues**: kuraterte paletter lagt på en ekte nettside, med navngitte roller: «Elements» (Background, Headline, Sub headline, Button, Button text, Card background, Card headline, Card paragraph, Card text highlight, Card tag background, Card tag text), «Illustration» og «Icons» (Stroke, Main, Highlight, Secondary, Tertiary), «Newsletter» (Background, Input, Label, Placeholder, Button, Button text). Siden viser nav, hero, kort, knapper, skjemafelt, lenker og illustrasjoner. Formål: vise «how and where you could use the colors» — [Happy Hues](https://www.happyhues.co/)
- **uicolors.app** (Tailwind-skala 50–950): «Create and visualize Tailwind colors on all sorts of components and designs.» Forhåndsvisninger: Cards, Shadcn/ui-komponenter, Website, Branding, Dashboard, Apps, Charts, Gradients, Logos, Headings. Kan «Add success, info, warning, and error color scales» og «Add a custom neutral color scale for standard UI elements like text, borders, and surfaces». Kontrast finnes som eget verktøy («Website Contrast Check»), ikke integrert i forhåndsvisningen — [uicolors.app](https://uicolors.app/)
- **Coolors Palette Visualizer**: fem malkategorier – «Mobile/Web UI», «Branding», «Typography», «Pattern», «Illustration»; «Preview your colors on real designs for a better visual understanding». Kontrast ligger i et separat «Contrast Checker»-verktøy — [Coolors Visualizer](https://coolors.co/visualizer)
- **Huemint** (website-mal): roller «Background», «Text/foreground», «Accent» (1–3), maler «Monochrome» og «Magazine»; «Creativity»-glider («Higher creativity will result in more random and potentially creative results. Low temperature will result in more 'average' or typical colors»), generering med «Transformer AI», «Diffusion Model AI», «Random Creative»; «Contrast Matrix»: «Enter a number between 0-100, where 0 = 'any contrast', 1 = no contrast, 100 = maximum contrast (black/white)»; låsing av farger; forhåndsinnstillinger Default, High Contrast, Pastel, Vibrant, Dark, Hyper Color — [Huemint website](https://huemint.com/website-1/)
- **Khroma**: «By choosing a set of colors, you'll train a neural network powered algorithm to generate colors you like and block ones you don't, right in your browser»; visninger «typography, gradient, palette, or custom image» (pluss «poster»); viser «WCAG accessibility rating of each pair». Ingen komponentforhåndsvisning — [Khroma](https://www.khroma.co/)
- **Atmos** (atmos.style): «Build accessible palettes with APCA (WCAG 3) and WCAG 2»; «Semantic status colors»: «Generate success, warning, danger and info colors from your primary color»; bruker LCH/OKLCH; eksport til SVG, Figma, CSS, Style Dictionary, Tailwind, JavaScript. Landingssiden viser ingen komponentforhåndsvisning — [Atmos UI design](https://atmos.style/ui-design); [Atmos alternatives/uicolors](https://atmos.style/alternatives/uicolors)
- **Primer Prism** (GitHub): «a tool for creating and maintaining cohesive, consistent, and accessible color palettes» — [github.com/primer/prism](https://github.com/primer/prism). Selve verktøysiden ga tomt innhold ved henting.
- **Figma-plugin «Foundation: Color Generator»**: «generates a complete color system from a single base color», «semantic, text, and supportive colors created automatically», støtter primary/secondary/tertiary, automatisk navngiving og eksport av tokens — [gluestack blog (2025)](https://v2.gluestack.io/blogs/creating-a-color-palette-from-scratch); [uxdesign bootcamp](https://bootcamp.uxdesign.cc/6-wonderful-color-plugins-on-figma-9aab7588cc9b)
- **Figma-plugin «Supa Palette»**: «enabling the creation of harmonious, accessibility-oriented palettes and streamlining the design process when building design systems» — [Figma color palette generator-side](https://www.figma.com/color-palette-generator/)
- **Material 3 Expressive / Theme Builder i Figma**: komponentene «are designed to be responsive to dynamic color, applying Material's new color roles in a consistent and comprehensive way» — [material.io blog](https://material.io/blog/start-building-with-material-you)

### Inferences
- Verktøyene deler seg i to klasser: *palettverktøy* (Coolors, Huemint, Khroma, Happy Hues, Realtime Colors) som mapper 3–5 flate farger på en side, og *skala-/tokenverktøy* (Material Theme Builder, Radix custom palette, uicolors.app, Atmos, Primer Prism) som genererer hele toneskalaer og lar designsystemets regler bestemme hvilke trinn som brukes hvor. Et «komponentforslag» i Kolorist bør kombinere begge: foreslå roller fra paletten og utlede tilstandstrinn fra en skala.
- Kontrast-tilbakemelding gis nesten alltid globalt (per fargepar) i stedet for per komponent; bare Realtime Colors knytter rød/gul/grønn-merking til tekstparene som faktisk brukes i forhåndsvisningen.
- Ingen av palettverktøyene viser hover/trykket/fokus/deaktivert; dette er en åpen nisje for en app som viser tilstandene side om side.

### Gaps
- Figma-pluginsidene (Foundation: Color Generator, Supa Palette) svarte 403; detaljer om hvilke komponenter de forhåndsviser er ikke bekreftet fra primærkilde.
- Primer Prism-siden (primer.style/prism) og Atmos' «Playground» ga ikke lesbart innhold; om de har komponentforhåndsvisning er ukjent.
- Coolors-siden var avkortet; hvordan Coolors tildeler palettfarger til elementer i «Mobile/Web UI»-malen er ikke dokumentert.

## 2. Konvensjoner for å mappe en palett (50–950 / Radix 1–12 / Material tone 0–100) på komponenter

### Takeaway
Tre tydelige konvensjoner finnes: (a) **Radix 1–12**: 1–2 bakgrunner, 3–5 komponentbakgrunn normal/hover/aktiv, 6–8 kantlinjer (8 = fokusring), 9–10 solid knapp normal/hover, 11–12 tekst; (b) **Material 3 toner**: primary 40 (lys) / 80 (mørk), on-primary 100/20, primary container 90/30, surface 98/6, outline 50/60, error 40/80, error container 90/30; (c) **Tailwind/Primer/Carbon-lignende 10-trinns skalaer**: 50–100 (Primer 0–1, Carbon 10) som tonet bakgrunn for varsler, 200–300 (Carbon 20–30) kantlinjer, 500–600 (Carbon 60, Primer 5, Fluent brand 80) som knapp/lenke, 700–800 som hover/aktiv/tekst på tonet bakgrunn.

### Cited Findings

**Radix Colors (12-trinns skala, v3, 2024)**
- Bruksområder per trinn: 1 «App background», 2 «Subtle background», 3 «UI element background», 4 «Hovered UI element background», 5 «Active / Selected UI element background», 6 «Subtle borders and separators», 7 «UI element border and focus rings», 8 «Hovered UI element border», 9 «Solid backgrounds», 10 «Hovered solid backgrounds», 11 «Low-contrast text», 12 «High-contrast text» — [Radix: Understanding the scale](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)
- «Step 3 is for normal states. Step 4 is for hover states. Step 5 is for pressed or selected states.» «Step 6 is designed for subtle borders on components which are not interactive», «Step 8 is designed for stronger borders on interactive components and focus rings.» — [samme](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)
- «Step 9 has the highest chroma of all steps in the scale.» De fleste trinn 9-farger er laget for hvit tekst, unntatt: «Sky, Mint, Lime, Yellow, and Amber are designed for dark foreground text and steps 9 and 10.» — [samme](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)
- «Steps 11 and 12—which are designed for text—are guaranteed to Lc 60 and Lc 90 APCA contrast ratio on top of a step 2 background from the same scale.» — [samme](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)
- Radix Themes bruker trinnene slik: «Steps 3-5: Interactive components», «Steps 7-8: Borders and separators», «Steps 9-10: Solid colors», «Steps 11-12: Accessible text»; ekstra tokens `--accent-surface`, `--accent-indicator`, `--accent-track`, `--accent-contrast`; `highContrast`-valg som «achieves appearance that stands out against the page background» — [Radix Themes: Color](https://www.radix-ui.com/themes/docs/theme/color)
- Semantiske skalaer: feil «red, ruby, tomato, crimson»; suksess «green, teal, jade, grass, mint»; advarsel «yellow, amber, orange»; info «blue, indigo, sky, cyan». Grå velges etter aksentkulør: «choose the gray scale which is saturated with the hue closest to your accent hue» (mauve ~ lilla, slate ~ blå, sage ~ grønn, olive ~ lime, sand ~ gul) — [Radix: Composing a palette](https://www.radix-ui.com/colors/docs/palette-composition/composing-a-palette)

### Inferences
- Oversatt til en 50–950-skala (Tailwind/uicolors) er den vanligste mappingen (utledet fra Carbon 10–100, Primer 0–9, Fluent-eksemplet og Radix 1–12): 50 = sidebakgrunn/subtil flate, 100 = tonet varselbakgrunn og «soft»-knapp, 200 = hover på tonet flate / subtil kantlinje, 300 = kantlinje på input/outlined-knapp, 400 = plassholder/deaktivert tekst, 500–600 = solid knapp, lenke og fokusring, 700 = hover på solid knapp, 800 = trykket/aktiv og tekst på tonet varsel, 900–950 = overskrifter/høykontrast tekst. Carbon gir det tydeligste beviset (Blue 60 knapp → hover «halvtrinn» ~65 → aktiv Blue 80; Red 10 varselbakgrunn med Red 60 tekst/ikon).
- Material og Radix er enige om at knappetekst på solid primærfarge skal være nesten hvit (Material: tone 100 på tone 40; Radix: hvit på trinn 9) unntatt lyse kulører (Radix: sky, mint, lime, yellow, amber → mørk tekst). Kolorist kan bruke samme regel: velg hvit eller mørk tekst etter hvilken som gir høyest kontrast mot trinn 9/tone 40.
- Fluent-rampen går fra 10 (mørkest) til 160 (lysest), så brand 80 → hover 70 → pressed 40 betyr mørkere ved hover og mye mørkere ved trykk. Alle systemene går altså mørkere ved hover og enda mørkere ved trykk i lyst tema; i mørkt tema reverseres hover (Fluent dark: brand 70 → hover 80 = lysere).

### Gaps
- Atlassians fullstendige token-tabell (brand.bold/hovered/pressed, danger/success/warning/information, link.visited, border.focused, elevation.surface.*) kunne ikke hentes fra primærkilde (siden er JS-renderte, GitHub-speilets filstier ga 404, og unpkg-filen ble avkortet). Verdiene over fra shadcn.io er sekundære.
- Primers knappetokens (button-primary-bgColor-hover osv.) og `focus-outlineColor` lå utenfor det avkortede JSON-utdraget.
- Adobe Spectrum (color-fundamentals, states) ga 404 på begge forsøk; Spectrums regel om «ett indekstrinn per tilstand» er derfor ikke dokumentert her.

## 3. Eksplisitte tilstandsregler (hover, trykket, fokus, deaktivert) per system

### Takeaway

- Atlassians eksplisitte regel for hvor mange palettsteg hover/pressed flytter (f.eks. B700 → B800 → B900) ble ikke funnet i primærkilde.

## 4. Tilgjengelighetsregler for komponenter (WCAG 2.2, APCA)

### Takeaway
WCAG 2.2: tekst 4,5:1 (stor tekst ≥18 pt / 14 pt fet: 3:1), komponentgrenser og fokusindikatorer 3:1 mot tilstøtende farge (1.4.11), fokus må ikke skjules helt (2.4.11, AA) og på AAA (2.4.13) må indikatoren dekke minst et 2 px-omriss og endre kontrast 3:1 mellom fokusert og ufokusert; deaktiverte komponenter er unntatt. APCA: Lc 90 brødtekst, 75 minimum brødtekst, 60 annen tekst, 45 stor/fet tekst, 30 absolutt minimum tekst og store ikke-tekst-elementer, 15 grense for «discernible».

### Cited Findings
- WCAG 2.2 SC 1.4.11 (AA): «The visual presentation of the following have a contrast ratio of at least 3:1 against adjacent color(s): User Interface Components … Graphical Objects». «This success criterion does not require that controls have a visual boundary indicating the hit area. If a control has visible content (such as text or a sufficiently contrasting icon), which helps users identify the presence of the control, then a border or other indication of the overall boundary of the hit area is not required». Fokus: indikatorer «must have sufficient contrast against the adjacent background when the component is focused, except where the appearance of the component is determined by the user agent and not modified by the author». Unntak: «User Interface Components that are not available for user interaction (e.g., a disabled control in HTML) are not required to meet contrast requirements.» Eksempel som består: tekstfelt med «a grey border (`#767676`) and white adjacent color outside the component» — [W3C Understanding 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- SC 1.4.3 (AA): «The visual presentation of text and images of text has a contrast ratio of at least 4.5:1»; stor tekst «at least 3:1»; stor tekst = «at least 18 point or 14 point bold»; unntak for «Text or images of text that are part of an inactive user interface component, that are pure decoration …» og logotyper; 1.4.6 (AAA) 7:1 — [W3C Understanding 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- SC 2.4.11 Focus Not Obscured (Minimum), AA: «When a user interface component receives keyboard focus, the component is not entirely hidden due to author-created content.» «if the focus indicator is fully obscured, it would likely fail 2.4.7 Focus Visible.» — [W3C Understanding 2.4.11](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)
- SC 2.4.13 Focus Appearance, AAA: indikatoren «is at least as large as the area of a 2 CSS pixel thick perimeter of the unfocused component or sub-component» og «has a contrast ratio of at least 3:1 between the same pixels in the focused and unfocused states» — [W3C Understanding 2.4.13](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html)
- APCA (SAPC-APCA «APCA in a Nutshell», Myndex): Lc 90 «Preferred level for fluent text and columns of body text with a font no smaller than 18px/weight 300 or 14px/weight 400»; Lc 75 «The minimum level for columns of body text with a font no smaller than 24px/300 weight, 18px/400, 16px/500 and 14px/700»; Lc 60 «The minimum level recommended for content text that is not body, column, or block text» (≥ 48px/200, 36px/300, 24px/400, 21px/500, 18px/600, 16px/700); Lc 45 «The minimum for larger, heavier text (36px normal weight or 24px bold) such as headlines, and large text»; Lc 30 «The absolute minimum for any text … 'spot readable'» og «large/solid semantic & understandable non-text elements»; Lc 15 «The absolute minimum for any non-semantic non-text that needs to be discernible … Designers should treat anything below this level as invisible». AAA-ekvivalent: +15 Lc på hvert nivå — [APCA in a Nutshell](https://github.com/Myndex/SAPC-APCA/blob/master/documentation/APCA_in_a_Nutshell.md)
- Radix garanterer «Lc 60 and Lc 90 APCA» for trinn 11 og 12 på trinn 2-bakgrunn — [Radix](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)
- Carbon: deaktiverte komponenter «are not subject to WC3 contrast compliance standards» — [Carbon v10](https://v10.carbondesignsystem.com/guidelines/color/overview/)
- Apple HIG Dark Mode: «At a minimum, make sure the contrast ratio between colors is no lower than 4.5:1. For custom foreground and background colors, strive for a contrast ratio of 7:1, especially in small text.» — [Apple HIG Dark Mode (JSON)](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/dark-mode.json)
- Apple HIG Color: «Avoid relying solely on color to differentiate between objects, indicate interactivity, or communicate essential information.» «If you define a custom color, make sure to supply light and dark variants, and an increased contrast option for each variant that provides a significantly higher amount of visual differentiation.» — [Apple HIG Color (JSON)](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/color.json)
- Fluent 2 har en egen «accessible» strek: `colorNeutralStrokeAccessible = grey[38]` (lys) / grey[68] (mørk), i motsetning til `colorNeutralStroke1 = grey[82]` / grey[40] — [lightColor.ts](https://raw.githubusercontent.com/microsoft/fluentui/master/packages/tokens/src/alias/lightColor.ts); [darkColor.ts](https://raw.githubusercontent.com/microsoft/fluentui/master/packages/tokens/src/alias/darkColor.ts)

### Inferences
- For en komponentforhåndsvisning bør kontrasten sjekkes per *par* i komponenten: (1) knappetekst mot knappeflate 4,5:1 (eller APCA Lc ≥ 60–75 for 14–16 px); (2) knappeflate eller input-kant mot sidebakgrunn 3:1 (1.4.11) – gjelder outlined-knapp, input-kant, avkrysningsboks, ikoner; (3) fokusring mot både bakgrunn og komponent 3:1; (4) tonet varsel: tekst mot tonet bakgrunn 4,5:1, og tonet bakgrunn trenger *ikke* 3:1 mot siden hvis det finnes kant/ikon/tekst som markerer den; (5) deaktivert: unntatt, men bør være ≥ Lc 15–30 (synlig).
- Fluents «StrokeAccessible» (grey 38 ≈ 3:1 mot hvit) vs. «Stroke1» (grey 82) viser at mange systemer bevisst har *to* kantfarger: en dekorativ (under 3:1) og en som brukes når kanten alene definerer komponenten (input, avkrysning). En app bør merke hvilken som gjelder.

### Gaps
- Ingen primærkilde funnet som angir en APCA-terskel spesielt for *fokusringer* eller *komponentkanter* utover Lc 30/15-nivåene i Nutshell-dokumentet.
- WCAG 3-utkastets status for APCA i 2026 er ikke undersøkt her.

## 5. Hvordan mørk modus endrer mappingen

### Takeaway
Alle systemene speiler skalaen, men ikke symmetrisk: primærfargen flyttes til en lysere, mindre mettet tone (Material tone 40 → 80; Fluent brand 80 → 70/100 for tekst; Carbon Blue 60 → Blue 50 for status/lenker), bakgrunner blir nesten-sorte med lysere «hevede» flater (Material surface Neutral 6 med container 4–24; Apple «base» og «elevated»), hover/trykket går *lysere* i stedet for mørkere, kantlinjer blir ofte halvgjennomsiktig hvit (shadcn border = white 10 %, input = white 15 %), og fokusringen bytter fra blå/svart til hvit (Carbon, Fluent).

### Cited Findings

- Apples faktiske verdier for base/elevated-bakgrunner (systemBackground vs. secondarySystemBackground) er ikke sitert.

## 6. Hvordan de beste verktøyene kommuniserer kontrast per komponent, og minimalt komponentsett for én forhåndsvisning

### Takeaway
Det finnes ingen etablert «minimumsskjerm» i kildene, men de tre verktøyene som faktisk viser UI (Realtime Colors, Happy Hues, Material Theme Builder) konvergerer om: navigasjonslinje, hero/overskrift + brødtekst, kort, primær- og sekundærknapp, skjemafelt med plassholder, lenker, og (Material/uicolors) status-/varselfarger. Kontrast kommuniseres som rød/gul/grønn-merke per tekstpar (Realtime Colors) eller som WCAG AA/AAA-sjekk (Material Color Tool, Khroma).

### Cited Findings
- Realtime Colors: komponenter = «headings, buttons, cards, and layouts»; kontrastmerking «x / Red … - / Yellow … ✓ / Green» — [Realtime Colors](https://www.realtimecolors.com/); [dev.to](https://dev.to/darwinphi/4-free-tools-to-visualize-your-color-palette-on-real-ui-components-18pe)

### Inferences
- Et minimalt, representativt sett for Kolorist («mini-appskjerm»), utledet av overlappet mellom Happy Hues, Realtime Colors og Material Theme Builder, og av hvilke tokens systemene faktisk skiller på:
  1. Navigasjonslinje med tittel og ett valgt element (viser surface-container / selected-trinn 5 / `sidebar-accent`).
  2. Kort med overskrift, brødtekst og dempet sekundærtekst på sidebakgrunn (viser surface vs. page, tekst 12/11, kant 6).
  3. Primær fylt knapp + sekundær (tonal/outlined) + tekstknapp, hver i tilstandene normal, hover, trykket, fokus, deaktivert (dekker trinn 9/10, 3/4/5, 7/8, 38 %-regelen).
  4. Tekstfelt med plassholder, fokusert kant og feiltilstand med hjelpetekst (kant 7 → fokus 8/aksent → error 9, tekst error 11).
  5. Fire varsler/badges: suksess, advarsel, feil, info (tonet bakgrunn trinn 2–3 / 50–100 med tekst/ikon 11 / 700–800).
  6. Lenke (normal og besøkt) og en bryter/avkrysning som bruker aksent («indicator»).
- Kontrast bør vises per par direkte i komponenten (som Realtime Colors) og ikke bare som en global tabell; hvert par merkes med WCAG-forhold *og* APCA Lc, og med hvilket krav som gjelder (4,5:1 tekst, 3:1 kant/fokus, unntak for deaktivert).

### Gaps
- Ingen kilde definerer eksplisitt et «minimumssett» av komponenter for å representere et designsystem; settet over er en syntese.
- Hvordan Material Theme Builder markerer kontrastfeil *per komponent* (om det skjer i forhåndsvisningen eller bare i «contrast level»-glideren) kunne ikke verifiseres fra siden; dev.to-artikkelen nevner bare «Built-in contrast checking (WCAG AA/AAA)» for Material Color Tool.
